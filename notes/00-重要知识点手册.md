## 二、Git 版本管理

| 知识点 | 要点 |
|---|---|
| 每天收工三连 | `git add .` → `git commit -m "描述"` → `git push` |
| 两个查看命令 | `git status` 看**现在**（有无未提交）；`git log --oneline` 看**过去**（提交历史） |
| **先 cd 再执行** | 不进项目目录就敲 git 会报 `not a git repository`。执行前先看提示符是不是 `PS D:\dev\python-practice>` |
| 提交信息前缀 | `feat:` 新功能 / `fix:` 修bug / `docs:` 文档 / `refactor:` 重构 / `chore:` 配置 / `merge:` 合并 |
| 首次提交要配身份 | 不配 `user.name` / `user.email` 会报 `Author identity unknown`，commit 直接失败 |
| 两条红线 | ❌ 不在 GitHub 网页端改文件（会造成冲突）；❌ 不用 `git push --force`（会抹掉远程提交） |
| `.gitignore` | 让 git 忽略不该跟踪的文件：`__pycache__/`、`venv/`、`.idea/`、`*.log` 等 |

## 三、变量与数据类型

| 知识点 | 要点 |
|---|---|
| 变量本质 | 贴着标签的盒子。`=` 是"把右边装进左边"，不是数学的"等于" |
| 四种基本类型 | `str` 字符串（带引号）/ `int` 整数 / `float` 小数 / `bool` 真假 |
| 命名三条铁律 | 只能用字母数字下划线；不能数字开头；不能是 Python 关键字 |
| 命名风格 | snake_case（小写下划线）：`user_name`、`total_score` |

## 四、输入输出与格式化

| 知识点 | 要点 |
|---|---|
| **input 永远返回字符串** | 想参与计算必须先转：`age = int(input("年龄："))` |
| 类型转换 | `int(x)` / `float(x)` / `str(x)` |
| f-string | `f"我叫{name}，今年{age}岁"` —— 最推荐的拼接方式 |
| 小数位数 | `f"{score:.2f}"` 保留 2 位小数；`f"{score:.0f}"` 取整 |

## 五、条件判断

| 知识点 | 要点 |
|---|---|
| `=` 与 `==` | `=` 是赋值，`==` 是比较。搞混是高频错误 |
| 执行规则 | if/elif/else **从上往下，命中一个就跳出**，后面不再看 |
| **条件从严格到宽松** | 范围小的写前面，范围大的写后面。写反了后面的分支永远走不到 |
| elif 只写上界 | 前面已经排除了小值，不用再写下界（写 `bmi < 28` 就够了） |
| **边界值必测** | 59/60、89/90 这种临界点最容易错，只测中间值（75）不够 |
| 逻辑运算符 | `and` 两边都真 / `or` 一边真 / `not` 取反 |

## 六、循环

| 知识点 | 要点 |
|---|---|
| **range 含头不含尾** | `range(1, 5)` 只有 1、2、3、4；`range(5)` 是 0~4 |
| for vs while | 知道跑几遍用 for；不知道跑几遍用 while |
| `while True` + break | 死循环必须靠 break 退出 |
| break vs continue | `break` 跳出**整个**循环；`continue` 跳过**本次**进下一次 |
| 嵌套循环 | **外层走一步，内层跑一圈** |
| **先判命中，再判次数** | 猜数字游戏：第 7 次猜中却被判"机会用完"，就是因为顺序写反了 |

## 七、列表 list

| 知识点 | 要点 |
|---|---|
| 下标从 0 开始 | 最大下标是 `len(lst)-1`；`-1` 是最后一个，`-2` 倒数第二个 |
| 切片含头不含尾 | `lst[1:3]` 取下标 1、2；`lst[:3]` 前三个；`lst[::-1]` 反转 |
| 增 | `append(x)` 末尾加；`insert(i, x)` 指定位置插 |
| 删 | `remove(x)` 删**第一个值**为 x 的；`pop(i)` 删**下标 i** 的并返回；`del lst[i]` |
| 查 | `len()` 个数、`x in lst` 在不在、`lst.count(x)` 出现几次、`lst.index(x)` 首次下标 |
| **`sorted()` vs `.sort()`** | `sorted(lst)` 返回**新列表**，原列表不变；`lst.sort()` 改**原列表**，返回 `None`。口诀：**sorted 有返回值要接，.sort() 没返回值别接** |
| 三种核心模式 | ① 筛选：空列表 + 循环 + `append` ② 计数：`count += 1` ③ **按下标修改：必须 `for i in range(len(lst))`** |
| ⚠️ 遍历中别改列表 | `for item in lst: item = 新值` 改的只是临时变量，列表不变 |

## 八、字典 dict 与集合 set

| 知识点 | 要点 |
|---|---|
| 一句话区分 | **列表靠数（下标），字典靠叫（键）** |
| **`[]` vs `get()`** | `d["不存在的键"]` 直接 **KeyError 崩掉**；`d.get("键")` 返回 `None`；`d.get("键", "默认值")` 给退路 |
| 增改删 | 增和改写法一样（看键以前有没有）；删用 `pop(键)` 或 `del d[键]`。**字典没有 append** |
| `in` 判断的是键 | `"name" in d` 判断键；想判断值用 `d.values()` |
| 遍历三种 | `.items()` 键+值（最常用）/ `.keys()` 键 / `.values()` 值 |
| **嵌套取值** | `d["a"]["b"]` —— 两个方括号**并排**，一层层剥。对应 JSON 对象 |
| 列表套字典 | 数据集标准形态，像 Excel 表格。取值 `students[1]["score"]` |
| 集合 set | 自动去重、**无序**（不能 `s[0]`）。去重组合：`list(set(旧列表))` |
| 集合运算 | `a \| b` 并集 / `a & b` 交集 / `a - b` 差集 |
| 元组 tuple | 不可变（`t[0] = x` 报错），用于坐标、日期这类不该改的数据 |
| 三种核心模式 | ① **打擂台**找最大：`top = data[0]`，循环比 `> top[...]` ② 计数器 ③ 筛选收集 |

## 九、函数

| 知识点 | 要点 |
|---|---|
| 定义 | `def 函数名(参数):` → 缩进 4 空格 → `return 返回值` |
| **return vs print** | `return` 把值交回（能接着用）；`print` 只显示（值是 `None`）。**核心原则：函数负责算，主流程负责打印**。不确定就用 return |
| 默认参数 | `def f(a, b=10)` —— **有默认值的参数必须放后面**，否则 SyntaxError |
| 作用域 | 函数是独立小房间：外面的变量里面能读；里面改同名变量是新建，不影响外面 |
| 判空列表 | `if not lst:` 比 `if len(lst) == 0:` 更简洁（Python 里"空的东西 = 假"） |
| 主动报错 | `raise ValueError("空列表没有最大值")` —— 比让程序报 IndexError 更清晰 |
| 入口保护 | `if __name__ == "__main__":` 只有自己运行才执行，被别人 import 时不执行 |
| 三个重构原则 | ① 一个函数只干一件事 ② 数据通过**参数**传进来，不读全局变量 ③ 用 return 交回结果 |
| 什么时候抽函数 | 同一段代码写 2 遍以上、或一段逻辑能独立描述 → 抽；只写一次很简单 → 不抽 |

## 十、字符串

| 知识点 | 要点 |
|---|---|
| 索引切片 | 和列表**完全一样**：`s[0]`、`s[-1]`、`s[1:4]`、`s[::-1]` 反转 |
| **字符串不可变** | `s[0] = "J"` 报 TypeError。**所有字符串方法都返回新字符串，原字符串不动**，必须用变量接：`s = s.replace(...)` |
| 大小写 | `s.upper()` / `s.lower()`。用于命令输入不区分大小写 |
| 去空白 | `s.strip()` 去两端 / `lstrip()` 左 / `rstrip()` 右。常用 `input().strip()` |
| 拆分 | `s.split(",")` 按逗号拆成列表；`s.split()` 默认按空格拆 |
| 合并 | `",".join(列表)` —— **分隔符在前，列表在后**。写反成 `lst.join(",")` 会报错 |
| 替换 | `s.replace("旧", "新")`，可用来去空格：`s.replace(" ", "")` |
| 开头结尾 | `s.startswith("x")` / `s.endswith(".py")` 返回 True/False |
| 查找计数 | `s.find("x")` 返回下标，**找不到返回 -1**；`s.index("x")` 找不到**报错**；`s.count("x")` 找不到返回 **0** |
| **`if s.find("e"):` 是错的** | 因为 `-1` 也是真值，会把"没找到"误判成"找到了"。要用 `if "e" in s:` 或 `!= -1` |
| f-string 进阶 | `f"{x:.2f}"` 2位小数 / `f"{x:,}"` 千分位 / `f"{x:.1%}"` 百分比 / `f"{x:^10}"` 居中宽10 |
| **格式说明符的点** | **精度前面必须有点**（`.2f`、`.1%`），**宽度不需要点**（`10`、`^10`）。`f"{x:.2}"` 是"2 位有效数字"不是小数，会输出科学计数法 |

## 十一、反复踩的坑（重点盯）

| 坑 | 正确做法 | 已踩次数 |
|---|---|---|
| **`for i in len(s)`** | `for` 只跟**容器**，不跟数字。要下标用 `for i in range(len(s))`，不然直接 `for item in s` | **2 次**（Day6、Day9） |
| 中文输入法混进代码 | 全角 `（）` `：` `＝` 会让 Python 报 SyntaxError。写代码前先看输入法 | 1 次 |
| 字符串方法没接返回值 | `s.replace(...)` 单独一行等于白调用，必须 `s = s.replace(...)` | 1 次 |
| 多步操作心算跳步 | 列表连续增删时，每一步都在纸上写下当前状态再算下一步 | 1 次 |
| `.gitignore` 中文注释乱码 | 编码不一致导致，功能无影响但不美观 | 1 次 |
| commit 号看错 | `a1d43ac` 里的 `1` 别看成字母 `l`，从 `git log` 直接复制 | 1 次 |

## 十二、贯穿全程的方法论

| 原则 | 说明 |
|---|---|
| **三种核心模式** | 筛选收集、计数器、打擂台 —— pandas 的 groupby、SQL 的 WHERE、Spark 的 filter 本质都是它们 |
| **不确定就用安全写法** | 取字典值不确定键在不在 → `get()`；结果后面还要用 → `return` |
| **边界值必测** | 59/60、0/-1、空列表、第一次/最后一次 |
| **报错不可怕** | 三段式看：报错原文 → 原因 → 解法。先确认"代码没丢"，再找原因 |
| **输出由代码决定，不由语感决定** | `f"{greeting}，{name}"` 输出"你好，张三"，不是"张三你好" |
| **一步一步来** | 多步操作心算容易跳步出错，把中间状态写下来 |
